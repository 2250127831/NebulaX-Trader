# Tick 数据源选型决策

## 选型结论

- **选择**：NASDAQ ITCH 协议
- **接入方式**：UDP 原始二进制流（io_uring 接收）
- **交易对手方**：无（信号发出后假设立即成交，不依赖外部撮合）
- **定位**：从网卡到网卡的全链路低延迟策略管道

---

## 1. 选型历程

### 1.1 最初考虑：openctp TTS + CTP C++ API

| 优点 | 缺点 |
|------|------|
| 免费模拟 Tick + 交易 | CTP .so 黑盒，无法优化网络层 |
| A 股全品种覆盖 | io_uring/DPDK 落地不了 |
| CTP C++ API 二进制协议 | 闭源私有协议，格式不公开 |

### 1.2 问题

CTP 的 .so 将网络层完全封装，意味着项目的核心技术——io_uring 收包、零拷贝解析、内核旁路——全都没有落地场景。项目变成"调 .so 回调的策略脚本"，而非低延迟交易基础设施。

### 1.3 转向：NASDAQ ITCH

ITCH 是全球低延迟交易领域的标准协议，架构完全开放：

| 对比项 | CTP .so | ITCH 开放协议 |
|--------|---------|---------------|
| 协议格式 | 闭源二进制，未公开 | 公开，文档完整 |
| 网络层 | .so 封装，无法介入 | UDP 原始包，全链路可控 |
| io_uring | 用不上 | 从头到尾可用 |
| DPDK/Kernel Bypass | 用不上 | V6 目标 |
| 免费压测数据 | 无 | NASDAQ 官方提供样本二进制数据 |
| 面试认可度 | 国内量化熟悉 | 全球量化团队都认 |

### 1.4 不对等关系

| 场景 | 方案 |
|------|------|
| 开发期管道调试 | ITCH 样本数据回放 |
| 解析器开发 | ITCH 协议文档 + 样本二进制包 |
| 吞吐压测 | ITCH 样本（一天千万级逐笔成交） |
| 全链路延迟测量 | 云服务器发 ITCH → 本机网卡收 → 管道 → 信号发出 → 网卡时间戳 |
| 迁移到 A 股 L2 | 技能可迁移（二进制协议解析 + io_uring + 无锁管道全部复用） |

## 2. 项目边界

### 本项目的范围（NX-Trader）

```
Tick 二进制流 ──→ [网卡 t1]
  → io_uring 收包
  → 零拷贝 ITCH 解析
  → SPMC 无锁广播
  → 多个 Worker 并行运行策略
  → RiskManager 检查（仓位/亏损）
  → OrderManager 记录订单
  → ExecutionEngine 发出信号 [网卡 t2]
```

**t1 ~ t2 之间的全链路是本项目的范围**。信号发出后假设立即成交，持仓同步更新，不依赖外部成交回报。

### 边界外的职责

| 模块 | 归属 |
|------|------|
| 订单簿撮合 | NebulaX（独立项目） |
| 交易所连接（CTP/XTP） | 执行系统（后续可对接） |
| 成交回报处理 | 执行系统 |
| PnL 统计 | 执行系统或独立模块 |
| 历史数据回测 | 回测框架（独立） |

## 3. 性能测量方法

### 测量目标

从 Tick 包到达网卡（t1）到策略信号离开网卡（t2）的间隔。

### 测量方法

```cpp
// 接收端：SO_TIMESTAMPING 取 t1
setsockopt(sock, SOL_SOCKET, SO_TIMESTAMPING, ...);
recvmsg(sock, &msg, 0);
// msg 中取出 t1（内核在网卡中断打的时间戳）

// ... 整个管道处理 ...

// 发送信号：SO_TIMESTAMPING 取 t2
sendto(sock, signal, len, 0, ...);
// send 完成时从 cmsg 取出 t2（网卡发送完成时间戳）

// 延迟 = t2 - t1
```

### 测试环境的组成

| 组件 | 作用 |
|------|------|
| 海外云服务器 | 以 UDP 高速回放 ITCH 样本数据 |
| 本机 | 运行 NX-Trader 完整管道 |
| ITCH 样本数据 | NASDAQ 官方发布的历史逐笔成交包 |

云服务器只负责发包，不参与延迟测量。t1 和 t2 都在本机网卡上取，网络传输不进入测量结果。

### 测量结果的解读

延迟来自于：

```
网卡收到包 → 内核协议栈 → 用户态 recv → 解析 → SPMC 入队
  → 策略 Worker 出队 → on_tick → 信号 → Risk → Order → send
```

每个环节都可以通过时间戳拆分，V1 即开始全链路延迟测量。


## 4. 未来迁移到 A 股 L2

ITCH 上积累的能力全部可迁移：

| ITCH 技能 | A 股 L2 对应 |
|-----------|-------------|
| UDP 二进制收包 | 同，io_uring 复用 |
| 消息类型码解析 | 换协议类型表 |
| 逐笔成交解析 | 深交所 STEP / 上交所 LWSP |
| 时间戳对齐 | 同 |
| 无锁管道分发 | 完全复用 |
| 策略调度 | 完全复用 |
