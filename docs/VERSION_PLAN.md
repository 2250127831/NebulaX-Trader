# NebulaX-Trader Version Plan


## 项目最终目标

NebulaX-Trader 是一个面向低延迟量化交易场景的高性能交易基础设施项目。

项目目标是构建一个接近真实机构交易系统的数据处理与交易执行框架，重点研究：

- 高性能行情接入；
- 低延迟 Tick 数据处理；
- 多策略并行计算；
- 高效订单管理；
- 风控与执行链路；
- 极限网络性能优化。


最终系统形态：

![目标架构图](images/目标架构图.png)




项目核心原则：

> 保持交易业务流程稳定，通过底层基础设施持续优化，提高系统吞吐和降低尾延迟。

# V1 - High Performance Trading Pipeline


## 目标

基于已有 NebulaX 高性能组件，直接构建低延迟交易数据通路。

该版本作为项目起点，不重复实现基础交易闭环，而是直接进入高性能架构。


## 主要内容

迁移并整合已有技术：

- io_uring 异步网络；
- 无锁 RingBuffer；
- Zero-copy 数据传输；
- Memory Pool；
- Object Pool；
- Cache Line 优化。


实现：

- 行情接收；
- Tick解析；
- 策略计算；
- 订单生成；
- 模拟执行。


形成完整但高性能的单策略交易链路。


## 相比基础版本提升

相比传统交易模型：

- 同步IO升级为异步IO；
- 普通队列升级为无锁队列；
- 动态内存分配升级为对象池管理；
- 减少数据复制。


预期提升：

- 提高Tick处理吞吐；
- 降低平均延迟；
- 改善P99/P999尾延迟。

# V2 - Parallel Market Data Processing


## 目标

解决高频 Tick 输入下单线程解析瓶颈。


## 主要内容

引入：

- Packet Ring；
- SPMC无锁队列；
- Parser Worker Pool。


实现：

- 原始 Tick 并行解析；
- Binary Protocol解析；
- Tick结构化转换；
- 顺序提交。


## 相比 V1 的提升

相比 V1：

- 行情解析从单线程升级为多消费者并行处理；
- 提高多核CPU利用率；
- 增强高频行情处理能力。


预期提升：

- 更高行情吞吐；
- 高负载下更稳定延迟。


---

# V3 - Multi Strategy Trading System


## 目标

支持多个策略同时消费 Tick。


## 主要内容

引入：

- Tick Broadcast Ring；
- 多消费者模型；
- Consumer Sequence管理。


实现：

- Tick数据单份保存；
- 多策略独立消费；
- 减少数据复制。


策略仅用于验证系统：

- 趋势策略；
- 动量策略；
- 均值回归策略。


## 相比 V2 的提升

相比 V2：

- 从单策略系统升级为多策略系统；
- 提升系统扩展能力；
- 降低多策略场景的数据复制成本。


预期提升：

- 支持更多策略实例；
- 提高整体资源利用率。


---

# V4 - Multi Market Data Support


## 目标

支持多个行情源同时接入。


## 主要内容

实现：

- 多交易所连接；
- 多行情源管理；
- Tick标准化；
- 行情聚合。


## 相比 V3 的提升

相比 V3：

- 从单行情源升级为多市场环境；
- 提高系统规模扩展能力。


预期提升：

- 支持更多交易品种；
- 提升真实交易环境适应能力。

# V5 - Low Latency Optimization


## 目标

针对完整交易链路进行系统级优化。


## 主要内容

引入：

- CPU Affinity；
- Core Isolation；
- NUMA优化；
- Huge Page；
- Cache优化。


使用：

- perf；
- FlameGraph；
- eBPF。


分析：

- Tick接收延迟；
- Tick处理延迟；
- 策略计算延迟；
- 下单延迟。


## 相比 V4 的提升

相比 V4：

- 从功能扩展阶段进入性能极限优化阶段；
- 定位关键延迟来源；
- 优化硬件资源利用。


预期提升：

- 降低P99/P999延迟；
- 提升系统稳定性。


---

# V6 - Kernel Bypass Networking


## 目标

探索极限网络性能。


## 主要内容

引入：

- DPDK；
- AF_XDP；
- Kernel Bypass。


优化：

- 用户态Packet处理；
- 网络路径；
- 数据复制。


## 相比 V5 的提升

相比 V5：

- 减少Kernel网络栈开销；
- 提升网络吞吐；
- 降低行情接入延迟。
